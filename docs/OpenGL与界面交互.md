# OpenGL 是怎么把我们的像素显示到屏幕上的

> 给组员的极简说明。看完不需要记住任何英文术语，只需要记住**一句话**：
> **我们从来不用 OpenGL 画图，我们只用它"显影"。**

## 1. 先分清四个角色

| 角色 | 代码 | 白话理解 |
|---|---|---|
| 画板 | `FrameBuffer` | 一张大数组，每个格子存一个像素的颜色。**我们所有的算法（画线、画圆……）都是在往这张数组里写数字** |
| 显影师 | `Canvas` | 每帧把画板内容搬上屏幕。**全仓库只有这一个文件碰 OpenGL** |
| 相框 | `Window` | 开一个窗口，把鼠标键盘的动静转告我们 |
| 画家之手 | `PaintController` | 听鼠标键盘的指挥，决定往画板上画什么、调用哪些算法 |

## 2. 程序启动时发生了什么（只发生一次）

1. `Window` 找操作系统开一个窗口
2. `Canvas` 做"显影"前的三件准备（`Canvas.cpp` 构造函数里带圈号的注释）：
   - **① 编译两个小程序**（见下面名词表里的"着色器"），拼成一条画图流水线
   - **② 备好一个大矩形**：四个角正好顶住窗口的四个角
   - **③ 在显卡内存里开一张空贴图**，尺寸和画板一样大

## 3. 每一帧发生了什么（循环，每秒几十次）

```
PaintController.render(画板)     ← 算法往画板数组里写像素（和 OpenGL 无关！）
        ↓
Canvas.present(画板)
   ⓪ 把整块画板数组复制进显卡里的那张贴图     ← CPU 把画交给 GPU
   ① 让 GPU 画那个大矩形：
      矩形每个点的颜色 = 从贴图上对应位置取一个像素
      （于是画板内容被"铺"满整个窗口）
        ↓
Window.swapBuffers()             ← 把刚画的这张图翻到屏幕上
```

所以你在屏幕上看到的画面 = 我们的画板数组的放大版。**画板变，屏幕跟着变**，仅此而已。

## 4. 名词白话表（按出现顺序）

| 术语 | 白话解释 |
|---|---|
| OpenGL | 显卡的标准遥控器。一整套函数，能让显卡干活 |
| glad | 遥控器的"配对器"。开机时把每个遥控器按键（函数）的地址查出来，之后才能按 |
| 着色器 shader | 跑在显卡里的小程序，只有两个：**顶点着色器**回答"画在哪"，**片段着色器**回答"每个点涂什么色" |
| 程序 program | 两个着色器拼好、链接成的一条完整流水线 |
| 纹理 texture | 显卡内存里的一张"图片"。我们每帧把画板数组灌进这张图片 |
| VBO / VAO | VBO = 存矩形四个角坐标的显存块；VAO = 一个备忘盒，记住"这堆数字每 2 个是位置、再 2 个是取色坐标"，免得每次重新解释 |
| 双缓冲 swapBuffers | 显卡有两张画布：一张你看得见，一张在后台画。画完整个一帧后一次性"翻面"，避免画到一半被看见（闪烁） |
| 为什么 v 取反（1.0 - vUV.y） | 我们数组第 0 行是画面**顶部**，贴图第 0 行是**底部**，方向相反，所以上下翻一下才正 |

## 5. 和代码的对应关系

| 文档步骤 | 代码位置 |
|---|---|
| ⓪ 上传画板进贴图 | `Canvas.cpp` 的 `present()` 里 `glTexSubImage2D(...)` |
| ① 画矩形 | 同函数末尾 `glDrawArrays(...)`，配好流水线和贴图后一句调用 |
| 窗口翻面 | `main.cpp` 主循环里 `window.swapBuffers()` |
| 每帧重画全部图形 | `PaintController::render()`——所以拖动控制点时旧图形不会消失 |

## 6. 唯一需要记住的事

**写算法时完全不需要懂 OpenGL。** 你的函数只拿 `FrameBuffer`，只调 `putPixel`。
显示是 `Canvas` 的事，你写的每一个像素都会自动出现在屏幕上。
反过来，`src/` 下除了 `Canvas.cpp` 和 `Window.cpp`，任何文件都不许出现 `gl` 开头的函数——这是仓库红线（见 AGENTS.md）。
