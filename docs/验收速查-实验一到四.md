## 一、开场 30 秒（建议背下来）

"我们四个实验共用一套自研 2D 绘图引擎，不是四个孤立 demo。所有图形都是 CPU 上手写算法算出的像素，写进内存画板 `FrameBuffer`，最后整块上传成一张 OpenGL 纹理贴满窗口。实验一解决'怎么画线和圆'，实验二解决'怎么填满、怎么裁掉'，实验三解决'怎么变换和交互编辑'，实验四解决'怎么用控制点生成光滑曲线'。"

## 二、调用链（老师问"结构"就画这个）

```
main.cpp
  → Window (GLFW 建窗 + 事件转发)
  → PaintController (模式状态机 + 两层渲染 + 自绘任务栏)
      → raster::drawLine / drawCircle / drawArc
      → raster::scanlineFillPolygon / scanlineSeedFill
      → raster::cohenSutherland / midpointSplit / cyrusBeck
      → curves::deCasteljauAt / sampleBezier / sampleBSpline
      → geom::Mat3 (平移/缩放/旋转)
  → core::FrameBuffer (putPixel 是唯一画点入口)
  → core::Canvas (唯一碰 OpenGL：上传纹理 + 画一个矩形)
  → 屏幕
```

两条边界：

- **算法层不知道 OpenGL 存在**。用 `--smoke` 可以不开窗口跑完全部算法。
- **界面不用任何 UI 框架**。任务栏是矩形 + 文字 + 自己算命中，全部经 `putPixel`。

## 三、四个实验卡片

### 实验一 · 图元生成（`src/raster/Rasterizer.*`）

必做：Bresenham 直线（任意斜率）、中点圆、指定起止角圆弧、线型/线宽。

- **直线**：全整数误差项 `e = 2dy - dx`；`|m| ≤ 1` 以 x 为驱动轴，否则交换 x/y 角色；四方向由 `sx/sy` 决定。
- **圆**：判别式 `d = 1 - R` 起步；`d < 0` 取正右像素（`d += 2x + 3`），否则取右下（`d += 2(x - y) + 5` 并 `--y`）；八分对称一次出 8 个点。
- **圆弧**：取整圆离散点按方位角过滤。屏幕坐标 0° = 正右，y 向下所以顺时针为正；`end ≤ start` 时补 360°。
- **线型/线宽**：16 位掩码 `0xFFFF`（实）/ `0xF0F0`（虚）/ `0x8888`（点）；线宽 1/3/5 用方形刷子。
- **关键细节**：线宽 > 1 时掩码下标要除以线宽，否则刷子会把虚线空档填满——这是我们踩过的坑。
- **为什么不用 DDA**：Bresenham 全整数，没有浮点累积误差。
- 画布外线段先做包围盒剔除，直接返回。

### 实验二 · 填充与裁剪（`src/raster/Fill.*`、`Clip.*`）

**填充（必做）**

- NET：按边的下端点 y 分桶；AET：逐扫描线加入新边、删除失效边、按 x 排序、两两配对填充。
- **半开区间 `[ymin, ymax)`**：上端 y 减 1。扫描线正好过顶点时，局部极值点算 2 个交点、非极值点算 1 个，不会多填或漏填。
- 左端 `ceil`、右端 `floor`：像素中心落在多边形内部才填充。
- **种子填充**：扫描线版本，栈里放每段最左代表像素；向左右扩到边界填一整段，再在上下两行找新段。栈空间远小于逐像素版本。

**裁剪（必做）**

- **Cohen-Sutherland**：4 位编码 左 0001 / 右 0010 / 下 0100 / 上 1000；两端编码或为 0 → 全可见，与非 0 → 全不可见；否则取窗外端点与所越过的边界求交。交点可能落在相邻边界之外，此时不能夹取，下一轮继续与真正的边界求交（教材循环语义）。
- **中点分割**：不断对分、丢掉完全不可见的一半，逼近到 1 像素精度；只用整数加法和折半，不需要除法。

**挑战**

- **Cyrus-Beck**：凸多边形窗口，参数区间 `t ∈ [t0, t1]`；有向面积定绕向，内法线 `(-dy, dx) × winding`；`w < 0` 收紧下限、`w > 0` 收紧上限，`t0 > t1` 判不可见。
- **常驻裁剪**：裁剪窗口独立于模式持续生效（`V` 开关）；显示层缓存 `clipCache_`，窗口内照抄提交层、窗口外黑底，只在内容/窗口/尺寸变化时重建。

### 实验三 · 变换与交互（`src/geom/Transform.*`、`src/ui/PaintController.*`）

- 3×3 齐次矩阵、列向量 `v' = M·v`；平移在第三列；绕任意点 = `T(p) · R · T(-p)`。
- 屏幕 y 向下，所以 `[c,-s; s,c]` 在视觉上是顺时针，和圆弧角度约定一致。
- **核心设计**：图形参数化存储（端点、圆心半径、顶点表、控制点），变换只改参数，像素由提交层重放重算。不是缩放位图，所以反复变换不失真。
- **交互**：点选（线/圆环 5px 容差，多边形内部或轮廓 5px）、Shift 加选、空白拖拽框选、8 向控制柄、Shift 45° 吸附、Ctrl 20px 步进、方向键微移、`+/-` 10% 缩放、`T/R` 旋转 5°、**右键拖拽任意角度旋转**（Shift 吸附 15°）、`G` 指定参考点、`Del` 删除、`Ctrl+Z` 撤销（快照栈）。
- **拖拽用起点快照重算**，不是逐帧叠加：参数是整数，逐帧取整会累积漂移。
- **种子填充绑定**：种子填充是像素记录，不能直接变换；图形有稳定 id，种子记 `parentId`，变换时用同一矩阵变换种子并钳回图形内部（圆投影到半径内，多边形找最近内点）。
- **挑战：对接拼接**——点 A 轮廓取对接点与切向，点 B 同样；绕 B 对接点旋转两切向夹角（±90° 内取最短），再平移到 A 的对接点。

### 实验四 · 曲线（`src/curves/Bezier.*`、`BSpline.*`）

- **Bezier**：de Casteljau 递推，每层相邻点按 `(1-t):t` 插值，n 层后剩一个点；数值稳定，几何意义是割角。n 阶时 `n = 控制点数 - 1`。
- 采样 128 段，依次连线。
- **B 样条（挑战）**：clamped 节点矢量，两端 `p+1` 重（0 和 1），内部均布；节点数 = 控制点数 + 阶数。Cox-de Boor 递推求基函数，`0/0` 按 0 处理。曲线过首末控制点。
- 阶数自动取 `min(degree, 控制点数-1)`，点不够就降阶，不越界。
- **交互**：模式 8 连点控制点、右键提交；控制点可抓取拖拽实时改形；`B` 键切换 Bezier / B 样条。

## 四、工程证据（被问"怎么保证对/快"时用）

- `--smoke`：**202 项断言**，无窗口。每节先 `clear()`，再对具体像素或返回值断言；含交互状态机模拟（事件 → 像素）；结束时打印 `smoke: 202 checks, 0 failed`。
- `--demo` / `--demo-ui` / `--stress-ui` / `--bench-ui`：四个无窗口入口，分别出演示图、UI 截图、越界压力、帧成本。
- 性能（Release，800×600，本机实测）：常驻裁剪矩形 **0.066 ms/帧**、关闭裁剪 0.067、凸多边形窗口 0.062、拖拽 + 种子填充 0.278。
- 越界防护：`putPixel`/span 全部夹边界；尺寸不变量 `assert`；`--stress-ui` 覆盖出界画线、拖出画布再拖回、8×8 极小裁剪窗。

## 五、预测提问与答法（按概率排序）

### A. 几乎必问

1. **这四个实验怎么串起来的？**
   共用 `FrameBuffer` 和同一套算法入口，`PaintController` 按模式调度；OpenGL 只负责最后显示。

2. **你说自己写光栅化，那 OpenGL 干什么？**
   OpenGL 只做一件事：把 `FrameBuffer` 上传成纹理，贴到一个铺满窗口的矩形上。线、圆、填充、裁剪全是 CPU 手写。

3. **Bresenham 为什么快？**
   全整数运算，只有加减和误差项比较，没有浮点累积误差。

4. **中点圆判别式怎么来的？**
   圆方程 `F(x,y)=x²+y²-R²`，取候选两像素的中点代入判断在圆内还是圆外，得到 `d` 的增量 `2x+3` 或 `2(x-y)+5`。

5. **扫描线填充的数据结构？**
   NET + AET：建表分桶 → 逐行加入新边 → 删除失效边 → 按 x 排序 → 两两配对填充。

6. **扫描线正好过顶点为什么不错？**
   半开区间 `[ymin, ymax)`，上端缩 1 像素，极值点算两次、非极值点算一次。

7. **两种矩形裁剪的区别？**
   C-S 直接求交、迭代次数少；中点分割只用整数折半、不求除法，逼近到 1px。C-S 通常更快，中点分割适合只有整数运算的硬件。

8. **变换后图形为什么不变糊？**
   参数化存储 + 重放，改的是端点和顶点，不是缩放位图。

### B. 算法细节

9. **填充边界为什么 `ceil`/`floor`？** 保证像素中心在多边形内部才填。
10. **AET 为什么要排序？** 排序后相邻交点成对，中间就是内部区间。
11. **自交多边形怎么办？** 奇偶规则，配对天然处理，交叉区按奇偶交替填/不填。
12. **圆弧角度怎么定？** 屏幕坐标 0° 正右、顺时针为正；整圆离散点按角度过滤。
13. **圆上的虚线为什么能均匀？** 虚线需要沿圆周连续的计数，所以先按角度排序去重再套掩码；实线跳过排序省开销。
14. **Cyrus-Beck 内法线方向怎么定？** 有向面积判绕向，`(-dy, dx)` 乘绕向。
15. **拖拽为什么用快照？** 参数是整数，逐帧叠加取整会漂移；从起点快照重算零累积。
16. **种子填充为什么不跟圆缩放？** 像素记录不随参数走；用 `parentId` 绑定、变换种子、再钳回图形内部。
17. **B 样条和 Bezier 有什么区别？** B 样条局部支撑、阶数与控制点数解耦；clamped 时首末点重合。
18. **控制点很多时 Bezier 会怎样？** 阶数升高、整体支撑，改一个点会影响整条曲线；B 样条可保持低阶、只影响局部。
19. **de Casteljau 复杂度？** 每个采样点 O(n²)；我们 128 段，控制点很少，开销可接受。
20. **扫描线每行都 `std::sort` 会不会慢？** 会，点是增量变化的，理想做法是插入排序或增量维护；当前点数少、实现简单，性能数据见上。可优化点。

### C. 交互与工程

21. **任务栏为什么自己做？** 课程不允许 UI 框架；OpenGL 本身不带控件；按钮是矩形 + 文字 + 自己算命中，和画布共用 `putPixel`。
22. **什么是两层渲染？** `committed_` 提交层缓存重算法结果（种子填充不必每帧重放），预览层每帧叠加当前操作与光标。
23. **怎么保证不越界崩溃？** 所有写入夹边界、尺寸不变量 `assert`、`--stress-ui` 压力脚本覆盖极端输入。
24. **性能怎么保证？** 提交层缓存、裁剪显示层缓存、任务栏缓存、span 级填充、`putPixel` 内联、垂直同步；`--bench-ui` 可复测。
25. **测试怎么做的？** 无窗口 202 项断言：像素级验证 + 状态机模拟；另有三张自查图和压力/性能入口。
26. **右键拖拽旋转怎么算角度？** 按下时锁定参考点和起始极角（`atan2`），之后角度 = 当前极角 − 起始极角；每帧仍从起点快照重算，拖一整圈也不会累积误差；`Shift` 把角度量化到 15°。

### D. 挑战题（老师若挑着问）

27. 圆弧任意起止角 → 已做（角度过滤）。
28. 凸多边形裁剪窗口 → Cyrus-Beck 参数区间。
29. 对接拼接 → 轮廓最近点 + 切向对齐 + 平移。
30. B 样条 → clamped 节点 + Cox-de Boor。

### E. 可能的"送命题"

31. **这段代码是你写的吗？讲一处你最得意的。**
    选一个具体坑讲"为什么"：线宽 × 虚线掩码放大、种子绑定 + 钳制、拖拽快照防漂移、AET 半开区间顶点计数。能讲清取舍就说明真做过。
32. **如果重做会改什么？**
    AET 用插入排序/增量维护、曲线自适应细分、抗锯齿、旋转控制柄（当前右键拖拽够用但不够显式）、图形列表空间索引。

## 六、现场演示脚本（约 90 秒）

1. `1` 拖一条斜线 → `S` 切虚线 → `W` 加宽（演示线型/线宽）。
2. `2` 拖圆；`3` 拖弧 → 第二次点击定终止角（两阶段提交）。
3. `4` 连点 4 个顶点 → 右键闭合；`F` 切填充/轮廓。
4. `5` 点多边形内部做种子填充。
5. `6` `K` 拖一个矩形裁剪窗；`M` 切 C-S / 中点分割；`V` 常驻裁剪开关；画错随时 `Ctrl+Z`。
6. `7` 点线选中 → 方向键/拖拽；Shift 多选 → 拖角柄缩放（按住 Shift 等比、按住 Ctrl 中心缩放）；**右键按住拖一下 = 任意角度旋转**（松手前按住 Shift 停在 15° 整数倍）；`J` 把两条线对接。
7. `8` 连点 4 个控制点 → 右键提交；拖控制点看曲线实时变；`B` 切 B 样条。

> 演示前先在窗口外点一下确保没有残留选中；每步做完停半秒，别一口气点完。
